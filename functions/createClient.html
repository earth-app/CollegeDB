      Creates a client: the router API bound to a configuration of its own.

      A client behaves as if it ran in a separate process. It shares no mapper, mapping cache, placement manifest or epoch, shard size cache, schema record, migration cache or phase observer with the module-level API, a scoped collegedb(config, callback) or any other client, even when they are given the same providers. Every method works the same as the function of the same name, and cached, invalidate and reconcileAllocations use the client's KV store, placement cache and coordinator.

      Nothing about a client needs AsyncLocalStorage: state travels with the object, so it is the isolation-safe choice on runtimes without an async context, and the one to use when several configurations serve requests in one isolate. The sync part of the configuration is applied before it returns, like initialize. Call initializeAsync on the client to wait for the background checks.
